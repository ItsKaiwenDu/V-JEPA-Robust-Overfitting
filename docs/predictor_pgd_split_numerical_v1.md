# Split numerical lifecycle integration

The new source builder separates the eight original/candidate EOT8 numerical
objectives from detailed profiling. It produces four **unbound ASTs**: the numerical
worker, its Capture class, versioned records and a v2 progress journal. The old
worker, numerical records, component route, hybrid reader and all frozen scientific
sources remain unchanged. No runnable university helper or authorization is ready.

## Preserved numerical and ownership checks

The builder SHA-pins four frozen source inputs. Twelve declared worker edits are
reversible to the original AST before explicit callback/filename/entry renames.
The original `common`, `idle`, no-grad scoring and gradient-context bodies remain
identical after the callback-name mapping. Model/parameter/target/mask/precision,
private-method/hook/flag/input-version/.grad/RNG checks remain. Eight objectives,
37 actual returns per objective, nonzero input gradient, original/candidate same
perturbed input, native L1 cotangents, selection-before-backward, seeds, projection,
restart/scoring/strict maximum selection and original loss/input thresholds stay.

The records retain exact source bodies for identity, native scope checks, typed
array loading and numerical comparison. The original frozen native/inner-task
proof callbacks retain their exact code bindings. Only explicit new record kinds,
filename rules, stricter row limits, journal completion gates and the 28-minute
numerical wall bound change. Removing the old full-model backend requirement is a
new scoped diagnostic definition; these records cannot qualify legacy workers or
claim full EOT8 kernels. The two proposed representative probes remain separate
and are not implemented or executed by this numerical source builder.

The numerical source has no profiler construction, materialization, old profile
summary or old backend validation call. It requests one genuine boundary observer
only on original objective zero, inside its native route at `EOT8-before`.
The observer is removed before native-route exit. Remaining objectives register a
no-op boundary cleanup stage; their journal stages do not imply a boundary capture.
The authenticated boundary provider and canonical storage/layout reconstruction
are still unbound and must be reviewed before any target work.

## Durable progress and versioned publication

`post-gradient-progress-v2.jsonl` is a new exclusive 0600 append/fsync journal in a
private 0700 folder. Limits remain 64 KiB, 64 rows and 1,024 bytes per row. Its
`provisional` field replaces `profiled`: only objective indices zero and one retain
bounded provisional native/VJP/scope/header metadata. No full-model profile is
implied. Per-file native/VJP limits now match the exact frozen split inventory.

The journal observes gradient return/checks, optional provisional metadata, hook
removal, boundary exit, native exit, restoration, input restoration, native proof
and final publication. Mandatory cleanup still runs when journal writes fail;
failures stop success and do not retry. Original exception context is retained.
A constructor failure can save an incomplete record without manufacturing a journal.

Objective files are `numerical.json`, `numerical-complete.json` and
`numerical-failed.json`. The rollout header is `results/run-status.json`; it must
remain the numerical header while future coordinator progress uses its separately
budgeted supervisor record. New objective readers require a validated v2 journal
with all mandatory gates and the final publication return, no raised gate,
unreturned stage, incomplete tail or failed marker. A header/completion marker
written just before a final journal fsync failure is deliberately **insufficient**.
No journal or versioned numerical receipt alone admits CUDA execution, backend
coverage, performance, replay, scientific adoption or training.

## Typed result I/O

`predictor_pgd_split_store_v1` derives the frozen 419-path result/log namespace and
refuses legacy filenames, unknown/noncanonical paths, excessive extents, unsafe
modes/links/types/devices, unexpected directories and stale partials. It accounts
for shared metadata/trace caps and serial partials. Its byte writer creates only
private files, fsyncs, checks held parent/named identities, refuses immutable
replacement and poisons itself on an in-flight publication error. Existing
committed file metadata is checked without repeatedly hashing every tensor.

Directory identity uses device/inode/uid/mode; directory link counts can change
when children are created. File single-link checks remain strict. Metadata scans
are not value hashes or authenticated lineage, and pre/post checks are not a
complete adversarial-race security proof. This local store covers **results/logs
only**. It does not implement tensor serialization, actual runtime resource
supervision, full input/code/cache/proof accounting, live free-space/inode checks
or same-session collection. Those remain required before a target package.

## Local verification

52 distinct checks are covered across 98 executions. The first run was 32 pass /
18 failures. Correcting the directory link-count assumption and strengthening
failure-cause assertions led to an affected-only run: 16 pass / 16 failures, with
20 unaffected initial passes excluded. Remaining failures were the opaque loss
fixture's missing `.sum()` interface; a token-returning stub fixed it without
arithmetic or production changes. Only those 16 failed cases reran and all passed.
Twelve previously passing negative checks were repeated because production I/O
and their cause assertions changed; their earlier broad exception checks could
otherwise accept an unrelated I/O error. Initial sources, failures and all three
snapshots/logs/JUnits are preserved. No old test suite or scientific cohort repeated.

All eight objective positions pass the new source/writer/journal/inventory
integration with explicit opaque callbacks. Failure cases now must reach their
intended gate. They cover journal open/fsync, missing/zero returns, comparison,
hook/boundary/native/input/model restoration, native proof, marker publication and
a post-marker journal failure. Other checks cover source drift, progress identity/
tails, private file constraints, typed paths, mutable/immutable publication,
stale partial preservation and directory replacement/mode changes.

The fixtures create tiny text tokens and ordinary metadata only. Files ending in
`.npy` are **not NumPy arrays**; native route, loss, gradients and proof validation
are explicit stubs. Compiled numerical/array-check source is inspected but never
executed. This is source/control-flow/I/O evidence, not numerical, actual native
ownership, CUDA scheduling, performance or timeout-resolution evidence.
