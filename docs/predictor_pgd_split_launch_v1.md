## Source and entry binding

The policy pins the original base/design/scratch contracts and existing host/GPU/
resource scope. Control preparation requires all six supervisor files; their sizes
and hashes join the policy text in canonical control bytes. The installation JSON
is derived after hashing that control, avoiding a self-referential hash. An exact
new single-attempt authorization must reference that control. Test authorization
metadata explicitly labels itself a simulation and is not a user grant.

The private source reader opens no-follow directory/file descriptors and checks
root/ancestor/held/named identities, size, mode and hash. The importer caches the
63 runtime files and six supervisor sources. It handles only declared `models`/
`attacks` names and refuses unknown project imports, ambient project modules and
reloads. Module origin/file paths remain bound to the private source tree. Installed
libraries and the unchanged upstream/checkpoint still have their original runtime
and source gates. This is not an in-process tamper-proof or hermetic environment
claim.

The child command uses isolated Python and explicit descriptor inheritance with a
fresh session, closed unrelated descriptors and private umask. These options use
Python's documented [process controls](https://docs.python.org/3.11/library/subprocess.html#subprocess.Popen)
and [isolated interpreter mode](https://docs.python.org/3.11/using/cmdline.html#cmdoption-I).
The [importer protocol](https://docs.python.org/3.11/library/importlib.html#importlib.abc.Loader.exec_module)
executes the already verified source bytes. These API choices are source-supported;
actual target behavior is unobserved.

## Parent ownership before release

The parent prepares the monitor before creating a child. A new child can execute
only standard-library bootstrap code while waiting on its inherited pipe. The
parent checks its new process birth/parent/session/group, holds its PID handle and
runs storage/GPU gates before writing the release byte. Failed binding closes the
only writer, giving the waiting child EOF. There is no numeric-PID signal fallback.
The child checks parent/session identity, exact saved control/authorization/session
bytes, role prefix, nonce, source hashes and continuing deadline. It checks owner
and deadline again after installing source namespaces and before dispatch.

The release-to-monitor handoff received an explicit correction during review.
Cleanup now checks the handle's actual closed state, including an exception before
the monitor's `finally` takes ownership. A monitor that returns with an open handle
is refused and the held child handle is stopped/closed. The parent never assumes
that assigning a Boolean transferred ownership. Kernel stop behavior, descriptor
support and cleanup under live target failures still require observation; no source
check can promise an uninterruptible process will stop instantly.

GPU gates retain the exact RTX 3070 UUID/driver and reject every other compute PID,
including a NoMachine process. They never stop that other process. Private logs
receive child stdout/stderr. Environment inheritance is limited to declared runtime
keys, four worker threads, one original GPU and scratch cache/tmp locations.

## Clocks, single use and receipts

One connection origin fixes the 2,400-second work and 3,000-second whole-connection
limits. Setup is checked against its original 180 seconds. Each role receives its
launch-origin 60/1,680/120/120-second cap, clipped by the work deadline and reserved
later phases/finalization/overhead. Source checks, saved-value verification and
publication are charged to that same phase. No child or callback resets a clock.
The [monotonic clock](https://docs.python.org/3.11/library/time.html#time.monotonic)
is system-wide; parent and child share this time domain on the one target host.
The future outer driver must still enforce login-inclusive client time, original
parent work/collection alarms and signal-safe failure collection.

Components retain the unchanged 120-second / observed 4 GiB RSS monitor. The proof
and numerical monitor is copied from that frozen source with four declared edits
for its two role clocks, sample counts, observation-only RSS and distinct receipt
kind. Its termination/handle cleanup body is retained. The component-only RSS cap
is not silently applied to model loading or the proof. No new resource allowance,
objective, warmup, reference or replay is introduced.

An exclusive session file is the durable per-root claim. Only the parent that
committed its previous session hash may replace it. A failed preflight or failed
exclusive claim cannot overwrite an older session. The outer preparation/attempt
claim and authorization mechanism must prevent reuse across roots; this per-root
state is not that missing outer mechanism. Native work starts only after numerical
receipts pass; the candidate starts only after native receipts pass. Successful
work returns `await-collection`, with completion and scientific admission false.

Concrete child dispatch retains the original packet, checkpoint, upstream, policy,
array file limits, allocator settings and fixed worker entries. Parent verification
uses the frozen/new saved numerical readers, boundary source hashes, component
completion journal and parent-resource join. These are saved-value checks, never
new objectives. Full actual source installation and scientific outcomes remain
unverified.
