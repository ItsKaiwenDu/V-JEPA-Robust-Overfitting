# Candidate-only component completion adapter

The new local worker adapter accepts only the forward-preserving candidate. It
reuses the completed native component and accepted eight-gradient/four-pair PGD
result, binds backend v4, and adds native-relative return checks before completion.
The emitted graph contains 39 files / 438,445 bytes. Its execution binding is null;
no university launcher, handoff, grant or target scope is prepared.

## Immutable references and source identity

The original 27,279,360-byte input capsule is unchanged. A separate deterministic
13,281,280-byte USTAR archive carries 18 unchanged native/reference records plus
one generated manifest. It includes the four native NPY returns, completed native
worker/resource/parent/ownership/backend/trace/progress records, original boundary
and capsule manifest, and the reviewed PGD/component/value/metadata provenance.
Native logical return hashes exactly match the original boundary. No native
component, complete cohort, clean replay or FP64 oracle is rerun to prepare it.

The input contract pins 62 existing files. The reference reader checks the closed
inventory, ordinary single-link private files, owner/mode/device, held file/parent
identity and exact hashes. The archive reader requires fixed member names, no
links/extensions, deterministic headers and exact reconstructed padding. NPY
headers and payload byte hashes are checked without decoding numerical values.
All actual serialized `.pt` source operands remain opaque during local preparation.

Historical source control, native component control and future candidate control
stay distinct. The reference binding carries the old native worker/resource/parent
hashes, original boundary/capsule identities and logical return hashes. Old controls
cannot be reused as a new candidate control. Source, reference and result roots
must be private, canonical and pairwise disjoint. One new namespace is single-use.

## Candidate-only lifecycle

The new entry, job constructor, completion reader, parent binder and result
inventory refuse the native role. The entry has no numerical-cohort dispatcher.
It adds no training policy or optimizer path. Scientific work in a future approved
worker remains one forward, one outer VJP and its one inner public-math VJP.

The source adapter adds three stages to the original lifecycle:

| Stage | Requirement |
| --- | --- |
| `reference_verify` | Bind the complete, read-only accepted native reference to the new candidate control and source boundary. |
| `accuracy_validate` | After raw/backend publication, compare all four actual candidate returns with native values under the original bounds; require byte-exact forward values. |
| `accuracy_publish` | Save the separately bound `accuracy.json` receipt before restoration, resource and completion publication. |

There are 23 required phases and 47 progress rows on a successful path, within
the unchanged 64-row/64 KiB progress limits. The candidate result inventory has
15 paths, including one new immutable 16 KiB metadata result. Native, full numerical
and source-boundary publication paths refuse. Shared metadata ceilings do not grow.

Only `_pgd_component_entry_v1.py`, `_pgd_component_job_v1.py` and the inventory
expression in `_pgd_component_store_v1.py` change from the archived runtime.
The read-only reference module gets bound manifest literals. Every tracked edit
has a complete byte inverse. All other retained runtime sources, including
scientific route, operands, compute, profiler, serializer, startup, reconstruction,
layout and runtime contract, remain byte-identical. Backend v3 is removed from
the emitted closure; reviewed v4 and all five pinned projection files are included.

The numerical decoder and agreement function are exact AST copies of the reviewed
saved-return helper; the bounds AST is unchanged. Output remains `rtol=1e-4,
atol=2e-5`; dQ/dK/dV remain `rtol=0.002, atol=2e-7`. NumPy loads only inside the
future worker value check, with the original 2.4.6 runtime. No canonical FP64
reference or full-model detailed trace is added.

The new completion reader verifies the reference and accuracy receipts in addition
to the existing source, outputs, ownership, raw/backend, progress and resource
joins. Parent validation checks receipt fields and byte identities; it does not
recompute numerical values or authenticate execution from a dictionary. Original
120-second component wall, 4 GiB sampled RSS, 7 GiB allocator and parent-identity
checks remain. These are retained validation/design constraints, not new resource
authorization or evidence of actual OS enforcement in this local test.

## Local checks and limits

All 25 distinct new checks have passing final results across 33 executions. The
first run had 17 passes/eight failures because the fake route omitted `values`
and `incoming` attributes required by the unchanged compute body. Only that test
fixture was corrected, and only those eight failed cases reran. Production bytes
and the 17 passing checks were untouched. No old suite or scientific cohort reran.

The checks cover byte inverses, exact scientific/numerical source preservation,
archive/reference lineage and drift refusal, candidate-only argument/inventory
rules, complete worker/parent metadata joins, and startup/reference/backend/value/
forward/restoration/allocator/deadline failures. The fake clock, profiler, route,
startup, allocator, parent observations and accuracy callback are explicitly
substituted. Their opaque output bytes and fake comparison summaries are not a
numerical or CUDA result. No Torch/NumPy, tensor/array value decode, real gradient,
profiler, process/RSS observation, GPU, proof, signal, timer or network runs.

The first cold build refused an ambiguous metadata-schema line before emitting
source. Its correction selects complete function spans for the three schema edits;
the second build emits the reviewed graph. Both logs and all source snapshots stay.

The independent standard-library audit v2 verifies 26,055 prior hashes / 28,102
prior fixture entries, 62 input pins, source inverses, unchanged scientific bytes,
numerical ASTs, an independent archive reconstruction and simulated receipt/progress
joins. It imports no project/test callbacks and decodes no numerical values.

Its first version refused a changed Mac filesystem device number: recorded
16777229, current 16777231. The tracked directory inode, owner, mode and authorized
link-count/mtime state match. Current APFS mount metadata is saved, and v2 requires
all prior fixture lstat devices to match the observed current repository device
while preserving every file hash and other recorded fixture field. The cause of
the device-number change and historical physical-volume identity are not asserted.
Original device records stay unchanged; this local preservation observation does
not alter any university device binding or live storage/GPU guard. The old FIFO
is inspected only with lstat and never opened, read or hashed.
