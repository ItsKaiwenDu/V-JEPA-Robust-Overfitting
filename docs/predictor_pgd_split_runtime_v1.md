# Split runtime source assembly

The local assembler emits 63 Python source files (12 generated namespaces and 51
unchanged dependencies) from a 70-file pinned input contract. The emitted worker
entries have concrete imports and internal bindings, instead of accepting caller
callbacks. The package is source only: no generated scientific module has been
imported, installed on a target or executed. There is no CLI, university helper,
new authorization or launch in this stage.

## Fixed namespaces and frozen behavior

The new numerical namespace imports the split records, v2 progress and new
original-boundary observer directly. The component namespace imports the frozen
startup, canonical operand providers, original/candidate route, raw extractor and
hybrid metadata reader. All literal project imports, including lazy imports, have
exact source bytes in the emitted graph; compiler-only false branches are not
runtime dependencies. Both package initializers remain inert. Scientific libraries
and the separately pinned upstream/checkpoint/training packet are external inputs;
this source graph does not replace their original guards.

The three frozen arithmetic bodies, canonical reconstruction, startup, scientific
comparison/array readers and native scope checks are preserved. The old writer
module is copied to a separate facade namespace; its globals and those of existing
modules are never modified. Only the new record's transport uses the split typed
store. Array detach/CPU/contiguous/NumPy/copy and serialization order remain, and
nonfinite returns are saved before rejection. No new objective, cast, analytical
reference, warmup, replay or completed-cohort repeat is introduced.

Component startup retains its one configuration owner and sets the original four
worker threads. After the pinned numerical/boundary readers return, the binding
rehashes the numerical header and compares the complete captured runtime (excluding
the model-specific execution field) before reconstructing operands. The existing
provider requires the actual attention flags to match the captured original. Final
restoration rechecks startup, runtime, four threads and attention flags. The original
component route still owns GraphTask/hooks/token/flags/version/RNG restoration.
No runtime callable can be supplied through the exact entry argument schema.
A future trusted bootstrap must verify/install these bytes in a fresh child and
bind arguments to its reviewed control; this is not an in-process tamper-proof or
hermetic-import security claim.

## Typed publication across hook threads

Autograd observation callbacks can execute on a different thread from their
creator. A new process-owned adapter serializes all publications with a reentrant
lock and refuses recursive writes. Each operation constructs the unchanged typed
writer on the calling thread, retaining that writer's ownership check. Committed
file metadata and permanent poison state are shared by the one process. A changed
PID, changed earlier publication, failed writer or second namespace binding refuses.
The original store source and its directory/file/partial/category/byte policies are
unchanged. The adapter does not create a second parallel writer or reset failures.

New numerical arrays serialize to a bounded byte buffer and publish through that
same typed store. Reads stay within its finite namespace and per-file cap, compare
held/named/scan metadata and detect replacement or extent changes. Source hashes
are computed from those bounded bytes. No tensor loader or scientific operation is
part of the I/O adapter. These guards do not yet account for setup/input/code/cache/
proof namespaces, live free space/inodes, or all adversarial filesystem races.

## Local checks and evidence

50 distinct new checks have passing latest results across 67 executions. The first
run passed 44 and failed one: a top-level Torch import changed CPython's compiled
attribute-call form in the frozen reconstruction body. The correction uses a fixed
import alias and assignment; the original body and exact compiled-code comparison
remain unchanged. Initial sources, emitted package, failure and JUnit are preserved.

The second run passed 22 checks: the failed check, 16 checks affected by the new
import/header binding, and five new cases. The 28 unaffected initial passes were
not repeated. New cases check the post-verification header hash and four opaque
serializer outcomes, including retained nonfinite and pre-existing evidence.
Existing scientific tests/cohorts were never called. The binding harness replaces
imports only in an explicit fake namespace; its startup/route/profile/compute calls
are opaque labels. The serializer's `.npy` files contain text, not arrays. The only
threaded execution publishes tiny ordinary byte fixtures. No real Torch/NumPy,
array math, model, autograd, profiler, child/process monitor, signal, GPU, SSH,
storage proof, retrieval, cleanup or paid work runs.

Raw source packages, snapshots and both runs are under
`runs/pretrained/diagnostic/predictor-pgd-split-runtime-v1-20261115`. The curated
saved-source review records independent source inverses, compiled-body comparisons,
closed import graph, old evidence hashes/layouts and saved result checks.
