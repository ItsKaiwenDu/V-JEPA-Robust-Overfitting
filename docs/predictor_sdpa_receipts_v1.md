# Saved SDPA receipt bookkeeping correction

The university v5 run remains failed and consumed. Its first worker saved complete
outputs and profiler evidence, but the parent reader demanded bitwise equality of
entire numerical-summary dictionaries. Saved-array review passes all original
error bounds; the only local reproduction difference is diagnostic relative L2
rounding. The actual remote parent did not save its recalculated dictionary, so
its exact scalar difference and reduction mechanism remain unobserved.

This separate policy preserves every numerical receipt field. All four returns
and all eight fields per return must be present, with strict JSON scalar types,
finite nonnegative metrics, positive four-dimensional shapes and original bounds.
Both independently recomputed and recorded elementwise checks must pass, with
zero failed elements and tolerance ratios at most one. Every field except
`relative_l2_error` must match exactly, including rtol/atol, shape, maximum error,
maximum tolerance ratio, pass/fail and failure count. No field is dropped or
rewritten. An exact zero-error receipt must keep exact zero diagnostic values.

Only the relative L2 diagnostic is compared using the already frozen bookkeeping
rule: `abs(recorded - recomputed) <= 1e-14 + 1e-12 * abs(recomputed)`. This explicitly
changes its receipt-validation rule from whole-dictionary exact equality; it does
not change elementwise tensor acceptance or create a new tolerance. Diagnostic
values outside that original bookkeeping bound, unknown/missing fields, coercible
booleans/strings, nonfinite values and forged passing claims all refuse.
The same policy covers canonical FP64 and passing-original comparison summaries.

A separate retrospective deep reader copies frozen v6 validation. Only the two
summary comparison statements and report plumbing change; normalized AST equality
is checked. Verified saved arrays are used to recompute the original comparisons.
Source, native input/layout/alias/anchors, canonical reference, runtime/precision,
startup, flags, actual profiled bytes, backend proof, serial predecessors, unique
processes, fresh replay and typed file/completion checks remain. Actual CUDA-domain
resource receipts are checked with the unchanged standard-library v3 adapter.

The public interface produces an explicitly retrospective assessment, never a
worker/authorization/cohort completion receipt. Saved path translations occur
only in memory. It cannot launch a model, worker, GPU, reference, profiler, SSH,
retrieval or paid compute. The pinned CLI checks all 195 existing target descriptors
and the unchanged failed-attempt review before assessing that first saved worker.
It creates a new local report exclusively and leaves the old rejection, producer
completion, claim, source and artifact hashes/modes/timestamps unchanged.

Focused tests use saved arrays and all twelve already completed CPU workers in
three prior cohorts, including math, serial and fresh replay. No new scientific
process or FP64 reference is needed. Rehashed false completion, corrupted arrays,
wrong source/runtime/input/trace/backend/startup, altered summaries and broken
fresh replay must still reject. Scientific execution and network/process creation
are blocked during these tests and independent review. Historical CPU/metadata/
handoff suites are not repeated or accumulated.
