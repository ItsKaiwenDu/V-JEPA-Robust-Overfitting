# Local small-upstream original-forward/public-math-VJP integration

The separate integration passes actual small-upstream model comparisons under the
unchanged native graph-ownership guard. It covers one mask draw with both original
mask families. It is not eight-draw EOT8, pretrained CUDA or research qualification.

## Scope and mechanism

The fixture is the pinned upstream V-JEPA architecture at synthetic tiny scale:
two encoder and two predictor blocks, two attention heads, 32 tokens, predictor
head dimension 32 and 128-dimensional predictions. All weights are locally seeded
fixture values; this is no released pretrained checkpoint. The original shared
FP64/native projection policy and clean frozen target encoder remain unchanged.

`LocalUpstreamRoute` refuses the university hosts, non-CPU/FP32 models, expanded
model geometry and changed source pins. It enters the unchanged native
`PredictorRoute` in original mode. Only the predictor instances' newly created
private functional aliases are composed with the new custom VJP. The original
native method wrapper and guarded SDPA function still execute and record every
actual original forward. Encoder routes, upstream global aliases, native method
identities, training registration and frozen source remain unchanged. A separate
local diagnostic marker identifies the custom derivative and is removed on exit;
no native passing-worker or training receipt is emitted.

The integrated Function returns original guarded SDPA values. Its backward delegates
to the frozen prototype's public-math VJP arithmetic, retaining input layout,
aliasing, versions and actual incoming gradient. The bridge reads the real root
identity from the existing `OwnedBackward` token. It adds no outer hook and never
calls native `_admit` just to admit a math operation: doing so would incorrectly
append model-recomputation evidence. Only the unchanged actual model/SDPA wrappers
may append those native call-thread records. Observation uses the native state
lock. Each internal math GraphTask and its three leaf hooks remain separately
observed by the frozen prototype.

Both creator-thread and actual separate-thread native backwards pass. Read-only
GraphTask identity inspection is unchanged in nature; computation uses public SDPA
and autograd APIs, with no private backend backward or fabricated saved states.
All instance-private aliases, methods, hooks and diagnostic markers restore on
normal completion and failure. Original source/study/execution policy stays.

## Actual evidence and tests

Four comparisons combine two fixed mask seeds (19 and 23) with creator-thread and
separate-thread execution. Each uses original-before, candidate and original-after
model evaluations, twelve actual tiny full-model loss/input-gradient evaluations
in total. Each evaluation uses one draw and both original mask families: contexts
of 8/24 tokens and predictions of 24/8 tokens. Both encoder and predictor use
nonreentrant activation checkpointing.

Predictions, clean targets, selected targets, scalar loss and every native L1
output cotangent are bitwise equal across before/candidate/after. Original input
gradients before/after replay exactly. Candidate input gradients pass the unchanged
rtol 0.002 / atol 2e-7 rule, with zero failed elements. Maximum absolute difference
is 1.28056854e-9; maximum error/tolerance ratio is 0.00392966345, below one. Model
state digests and parameter/input versions stay fixed, parameter gradients remain
absent, and all methods/hooks/markers restore.

Every evaluation retains sixteen native attention rows: eight primary and eight
actual checkpoint recomputations, covering both encoder and predictor blocks in
both families. The native root hooks and actual call threads verify. Candidate
runs contain four completed initial predictor VJPs plus four recomputation calls
within the frozen eight-call prototype bound. All four inner math GraphTasks are
distinct and belong to the observed native outer scope; all root/leaf hooks remove.

Thirteen distinct checks are covered. The initial suite has twelve passes and one
negative-fixture assertion failure: the foreign-graph injection was made under
math flags, so the unchanged guard also saw changed method flags and returned
`method-exit-flags` rather than the expected graph error. Only that fault fixture
changes, temporarily restoring original flags around the deliberately foreign
method call. The one corrected targeted check passes and records the exact native
`foreign-autograd-graph` refusal, different actual/expected graph IDs and complete
restoration. The first failure and exact source remain. No full suite or successful
model comparison repeats; counts are not summed. Production/scientific source and
all thresholds are unchanged after the first run.

A separate passing negative check disables checkpointing. The native guard still
refuses `backward-recomputation-unobserved`, with an empty call-thread list. This
proves the bridge's math operations do not impersonate model recomputation. Other
checks retain original two-family coverage refusal, source/alias/context identity
checks, setup/primary-error restoration and consumed-route refusal.

## Independent saved review and limits

Independent NumPy review verifies 120 actual saved FP32 arrays and their hashes,
reconstructs all native L1 cotangents from selected clean targets, recomputes full
input-gradient bound comparisons, and checks every native/root/inner/leaf receipt.
It imports no Torch/model library and executes no model, autograd, SDPA, CUDA,
process, network or new reference calculation. All 737 prior sealed inputs and
245 actual target byte/mode/timestamp descriptors remain unchanged. Initial and
corrected sources/logs are preserved, and new evidence is sealed.

Actual local runtime is arm64 Python 3.11.16, Torch 2.14.1 and NumPy 2.4.6. The
native guard and explicit-call prototype remain byte-identical. This does not
qualify Torch 2.8/CUDA, eight-draw native work, parameter/optimizer updates,
full-sized model memory, backend kernels, speed, study cost or full training.
The earlier target candidate rejection at 3,724 entries and financial gates stay.
No remote operator, target authorization, upload, cleanup, installation, held-out
pixels or paid work is created. No manual host/GPU status is needed now.
