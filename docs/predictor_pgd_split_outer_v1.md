# Attended split-work outer driver

The unarmed driver now connects exact source preparation, durable attempt claims,
private local scratch setup, the fixed serial coordinator, bounded observation
journals and same-SSH collection. It has one attended mode. A new scoped
university authorization is still required; no target connection or scientific
operation has run during preparation.

## Scope, source and single use

The source-only preparer reads the five frozen supervisors, the frozen collector,
63 frozen runtime sources and local driver files. It appends the new journal driver
to an unchanged coordinator prefix. Two copied methods differ in five explicit
places: a recorded preflight GPU gate, rebinding the journal to the verified guard,
the launch gate callback, and retention of owned child/lease references. The entire
original launch/stop/finally and preparation bodies are restored exactly by the
independent inverse check. Original scientific and worker code is unchanged.

Control binds all 69 uploaded source files, the outer stdin source, local driver/
entry-script hashes, the existing public SSH host key, original policy text,
repository and exact local handoff path. A new outer authorization binds that
control and its eight full gradients/two component VJPs, original budgets and
restrictions. No authorization is created during preparation. Saved test fixtures
contain invalid placeholder authorization files; fake approvals remain in memory.

The CLI refuses an unarmed handoff before importing the client or starting any
activity. A valid client checks all pinned inputs and creates `ATTEMPT.json`
exclusively before the single SSH invocation. Copying a handoff cannot change its
bound directory. Remote setup creates a deterministic private directory using
remote UID and outer control hash. That exclusive directory is the remote claim;
changing or retrying the connection cannot create another root under the same
control. Neither claim nor failed directory is removed or reset.

## Original clocks through login, setup and collection

The local clock starts at client entry; bound input checks and login are included
in its 3,000 seconds. The server sends a fresh nonce/hello and receives the elapsed
client duration sampled after hello receipt. It conservatively subtracts that
duration from its hello clock to obtain the original server origin. Setup stays
within origin + 180; work stays within origin + 2,400. Existing role clocks,
reserved finalization/overhead and the 60/1,680/120/120-second worker limits remain.

Default kernel SIGALRM is armed from the start for the applicable original hard
bound. A cancellable daemon Timer requests a best-effort main-thread notification
for earlier soft deadlines. It uses `_thread.interrupt_main`; it sends no OS/PID
signal. Cooperative checks independently reject elapsed phases. Generation tokens
and deadline checks ignore cancelled/stale notifications. Interruptions request
owned cleanup, with a default hard stop of at most two seconds clipped by the
existing allowance. Finalization may take over only after the recorded owned child
has exited and its process handle has closed. Worker monitors retain their frozen
PID-handle termination behavior; no numeric worker-PID fallback was added.

This split matters because [Python signal handling](https://docs.python.org/3.11/library/signal.html#execution-of-python-signal-handlers)
can be delayed by C code. The [main-thread notification API](https://docs.python.org/3.11/library/_thread.html#thread.interrupt_main)
schedules Python handling; it does not send a signal. [Timer cancellation](https://docs.python.org/3.11/library/threading.html#timer-objects)
is best effort, so the hard alarm does not depend on its callback. Kernel delivery,
uninterruptible tasks, actual stop/fit behavior and collection under live failures
remain unobserved; this is not an instantaneous-stop guarantee.

For local receipt verification, the client maps server deadlines using a causal
lower bound on clock offset: local send time preceded server receipt. It uses the
duration between that server receipt and its deadline, never compares remote and
local monotonic epochs, and clips to the original client limit. Collection remains
at most 600 seconds on the original connection. The source/header must match the
same claimed root and original phase clock before reconstruction. Only its bounded
header is read/replayed; physical network bytes are counted once.

The original 17,192,095-byte archive is received on the same stdin, hashed and

Existing checkpoint, upstream and dependency gates remain in the scientific code.
The old 16 MiB emergency extent requires real preallocation, without sparse or

The proof is still exactly one original worker; setup does not substitute a tiny
proof or run an objective.

Every live gate retains the original GPU/driver/UUID and other-compute-process
validation. Persistent successful samples occur at role changes and ten-second
intervals, while all intermediate checks still execute. Refusals are recorded
immediately when storage allows. The JSONL is capped at 512 KiB with bounded rows;
mutable storage status is capped at 64 KiB and may replace only its own committed
hash. Counters are bounded. Raw GPU text is bounded diagnostic data, with digest/
truncation metadata when needed. No foreign process is stopped. These sampled
observations do not reserve the GPU or claim continuous exclusivity.

A storage refusal never adds bytes to an already invalid tree. Its bounded
in-memory diagnostic can travel in the same-connection refusal frame. A retained
proof extent or other tree outside the original collection cap cannot be copied as
if complete. Failed setup/streaming leaves prior files intact; there is no cleanup,
new connection, automatic retry, rearming or download-only mode.

## Collection, local checks and readiness

After owned work ends, the collector prepares its combined receipt and fixed
manifest under the original work/finalization deadline. Only then does the driver
announce collection and stream through the same SSH stdout. The 3 GiB response cap
includes hello/claim/ready frames and the evidence stream. The client stores bounded
SSH stderr, root/refusal records, private copied evidence and its transport receipt.
A nonzero SSH exit is retained even if file transport verifies. All scientific and
training flags remain false pending independent review.

94 distinct new checks have passing latest results across 120 executions. Six
failing executions remain: three fake-clock fixture failures, two reproduced
cooperative deadline gaps and one hard-alarm design regression. Twenty passing
executions repeated only for changed source/package or affected timer paths.
Historical test functions and scientific cohorts were not repeated. Inverse AST,
metadata/protocol tests, invalid scope/claim cases, fake client/server lifecycles,
other-CUDA/storage refusals and tiny setup failures are covered.

All process, pipe, timer, signal, /proc, GPU and allocation bindings were fakes.
Only standard-library supervisor definitions execute. Runtime/scientific sources
are copied/compiled as bytes. Setup tests substitute installer/host/asset/proof
checks and use a zero-byte reserve placeholder with synthetic metadata. End-to-end
lifecycle tests inject inert worker/collector endpoints; they do not establish a
real Linux installation or full scientific run. Raw snapshots, failures, fake
receipts and earlier candidates are preserved.

The concrete final candidate stays unarmed. Its complete saved-source package,
